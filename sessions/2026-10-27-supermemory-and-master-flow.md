# Агентная сессия — 2026-10-27: Supermemory + «ОМА Мастер»

## Задача
Подключить Supermemory к проекту «ОМА Дом» и реализовать оставшиеся функции из `PROGRESS.md`: страницу «ОМА Мастер» с 10-шаговым флоу, маршрутизацию видов, память профиля/заказов/чата.

## Что сделано
- Установлен официальный SDK `supermemory@5.0.3` (namespace-first v5).
- Добавлен серверный слой `server/supermemory.ts` и plugin в `vite.config.ts`:
  - `GET /api/supermemory/status`
  - `POST /api/supermemory/search`
  - `POST /api/supermemory/add`
  - `POST /api/supermemory/profile`
  - `POST /api/supermemory/list`
  - Ключ читается из `SUPERMEMORY_API_KEY` (`.env`), в браузер не попадает.
- Клиентский слой `src/lib/supermemory.ts`: namespace на пользователя, профиль, ордера, чат, поиск фактов.
- `UserContext` синхронизирует профиль в `user_{id}` (извлечение памяти асинхронное).
- `MasterPage.tsx`: 10 шагов, демо-переключатель, чат с мастером, замена товара, Safe Deal, ПИН, приёмка.
- `App.tsx`: виды `catalog | product | master`, подключены `ProductPage`, `MasterPage`, `ProfilePanel`, `FloatingCartButton`, `MobileBottomNav`; удалён `ProductDetailModal.tsx`.
- `ProfilePanel.tsx`: простая карточка профиля — имя, телефон, город, карта, уровень и бонусы.
- `scripts/sync_supermemory.py`: убран hardcoded API key, инкрементальная синхронизация, `--force` для перезаписи; заливаются только проектные документы и `sessions/*.md`.
- Каталог товаров из Supermemory удалён (481 документ) по решению пользователя: в `omaweb_project` только контекст проекта и прошлые сессии.

## Финальные правки
- Профиль в `UserContext` синхронизируется только при изменении имени, города, телефона, карты или уровня; бонусный баланс не создаёт лишних записей.
- Мобильная навигация открывает простую карточку профиля.
- Чат сохраняет только последние две реплики с уникальным ID документа.
- Новый заказ после сброса получает новый `orderId`; записи заказа обновляются на шагах 2 и 5.
- Тестовые записи заказа удалены из `user_u_demo_1`, остался только профиль.
- Из `MasterPage` удалены вводный hero-блок и блок готовых сценариев (`HeroTaskEntry` / `WhyOmaDom`); экран начинается с шагов. Удалён бейдж «Дом» в шапке и футере, поиск переделан в единую плашку с кнопкой на всю высоту.
- Убраны «Память ОМА» и «Паспорт дома» из интерфейса и кода: `MemoryPanel` заменён на `ProfilePanel`, запись паспорта и его чтение удалены. Профиль, заказы и чат по-прежнему сохраняются в Supermemory без отображения в UI.

## Проверка
- `npm run build` — успешно.
- `GET /api/supermemory/status` → `{"ok":true,"hasKey":true}`.
- `POST /api/supermemory/add` для `user_u_demo_1` → `{"status":"queued"}`.
- Через ~30 секунд `POST /api/supermemory/profile` вернул 4 факта; `search` вернул факты о городе, уровне и предпочтениях.
- После очистки в `omaweb_project` остались `progress_md`, `homepage_md`, `context_md` и лог этой сессии.

## Замечания
- Извлечение памяти не мгновенное даже с `dreaming: "instant"`: в тесте профиль наполнился примерно через 30 секунд. В интерфейсе факты памяти больше не показываются.
- Vite middleware работает в `npm run dev` и `npm run preview`; для статического деплоя нужен отдельный API-сервер.
- Поиск по каталогу остаётся локальным (substring); семантический поиск по товарам убран вместе с товарными документами.
